# 算力平台

算力平台是多集群应用，在产品层面统一算力资源管理、模型服务、推理服务和 OpenAI-compatible API，内部按领域能力分层。

用户进入时无需先选择集群，首先看到全部已接入集群的全局算力与模型服务。创建模型服务或分配算力时，再选择资源落点。

## 算力资源

规划能力包括：

- 全局算力总览；
- CPU 和 GPU 资源；
- GPU 型号、显存、健康状态与使用率；
- 集群算力分布；
- 算力池；
- 资源、租户与项目配额；
- 算力分配与回收；
- 资源利用率与使用统计；
- 算力成本分析。

## 模型服务

规划能力包括：

- 模型注册与版本管理；
- 模型服务部署；
- 推理实例与副本；
- 模型启动参数；
- 服务扩缩容；
- 服务停止与恢复；
- 模型版本切换；
- 模型服务状态、日志和指标。

## API 服务

规划能力包括：

- OpenAI-compatible API；
- API Endpoint；
- API Key、权限、启用与禁用；
- 调用量与 Token 使用量统计；
- 请求延迟与错误率；
- 模型路由；
- 调用审计；
- 限流策略。

## 资源落点

规划中的资源落点方式包括：

1. 手动选择 Kubernetes 集群；
2. 选择算力池；
3. 由平台推荐集群；
4. 根据策略自动选择集群；
5. 将同一个逻辑模型服务部署到多个集群。

MVP 计划优先支持全局查看算力、手动选择集群、在指定集群部署模型服务，以及通过统一 OpenAI-compatible API 访问模型。跨集群自动调度尚未实现。

算力平台遵循以下资源关系：

- 算力资源可以全局查看，实际工作负载最终运行在具体 Kubernetes 集群中。
- 模型服务是全局逻辑资源，未来可对应一个或多个集群中的实际部署。
- 用户通过统一 API Endpoint 调用模型，不需要直接感知底层 Pod。

逻辑模型服务与实际部署的示例关系：

```text
qwen-production
├── cluster-guangzhou / 4 replicas
├── cluster-shanghai / 2 replicas
└── cluster-beijing / standby
```
